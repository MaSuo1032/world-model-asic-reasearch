# 05 · 與主流 LLM 的本質差異（多層面）

先說相同之處：這些模型幾乎全部由 **Transformer block** 組成，很多直接沿用 LLM/VLM 的 backbone（PaliGemma、Qwen3-VL、SmolLM2、Llama-2），核心 kernel 一樣是 GEMM、FlashAttention、RMSNorm/LayerNorm。所以「LLM 加速器能不能跑」答案是能；問題是**瓶頸的組成完全不同**，導致針對 LLM 最佳化的系統在這裡效率很差。

以下從十個層面比較。

---

## 1. 任務本質：預測什麼

| | LLM | VLA | 世界模型 | WAM |
|---|---|---|---|---|
| 預測目標 | 下一個 token 的機率分佈 | 未來一段**連續動作** | 未來的**觀測**（像素或潛變量） | 未來觀測 **+** 動作 |
| 輸出空間 | 離散、~10⁵ 類 | 連續、32–132 維 × 40–50 步 | 連續、數萬 token × 16–48 channel | 兩者 |
| 分佈特性 | 自回歸分解 | **多峰**（同一場景有多種合理動作）| 高維、時空相關 | 聯合分佈 |

連續、多峰的輸出是 VLA 改用 flow-matching / diffusion 動作頭的根本原因：用 softmax over bins（OpenVLA）或 BPE 動作 token（π0-FAST）都是把連續問題硬塞進 LLM 的離散框架。

## 2. 生成範式：一個一個生 vs 整塊精煉

| 範式 | 誰用 | 每次迭代處理 | 迭代次數由什麼決定 |
|---|---|---|---|
| 自回歸 decode | LLM、OpenVLA、π0-FAST | 1 個新 token | 輸出長度 |
| 迭代精煉（ODE/SDE 積分） | π0、GR00T、SmolVLA、Cosmos、Matrix-Game、DreamZero | **整塊**（50 個動作 / 整段影片）同時更新 | 取樣步數（35 → 蒸餾後 1–4） |
| 潛在空間搜尋 | V-JEPA 2-AC | 400 條候選軌跡平行 rollout | CEM 迭代數 |
| 塊狀自回歸 + 精煉 | Matrix-Game 2.0、DreamZero | 一個時間塊內精煉，塊間自回歸 | 兩者相乘 |

這是**最根本的計算差異**。LLM 的迭代次數 = 輸出長度，無法壓縮；flow/diffusion 的迭代次數是**超參數**，可以透過蒸餾（DMD、self-forcing、consistency）從 35–50 步降到 1–4 步而不改變輸出長度。Matrix-Game 2.0 是 3 步、GR00T 是 4 步、DreamZero-Flash 是 1 步。

## 3. 輸入：感測器串流 vs 文字

| | LLM | 機器人模型 |
|---|---|---|
| 輸入來源 | 使用者打字 / 文件 | 多路相機（30 Hz）、本體感測、語言指令 |
| 每次推論的 token 組成 | 幾乎全是文字 | **80–95% 是影像 token**（π0：768 / 816） |
| 輸入更新 | 偶爾 | 每次推論都是新的影像 |
| 原始資料量 | < 1 KB | ~0.5 MB（3 × 224²）到數 MB |

影像 token 主導序列長度，所以 VLA 的設計空間主要在**壓影像 token**（SmolVLA pixel-shuffle 16×、GR00T 2×2 merge、Wan2.2 VAE 16×16 空間壓縮）。

## 4. 狀態與記憶

| | LLM | VLA | 世界模型 |
|---|---|---|---|
| 狀態載體 | KV cache | prefix KV / hidden state | KV cache、latent 記憶幀 |
| 隨時間變化 | **單調增長**（直到 context 上限） | **固定大小**，每次重規劃整個丟棄 | 滑動視窗（固定）或檢索式 |
| 典型大小 | 1–17 GB（8B 模型，8K–128K） | **0.7–18 MB** | 1–8 GB |
| 管理方式 | PagedAttention、offload、壓縮 | 一塊固定 scratchpad | ring buffer（Matrix-Game 2.0）、依視野檢索重注入（3.0） |

大多數 VLA 本質上是**無記憶的反應式策略**：每次推論只看當下影像。長時記憶（Physical Intelligence 2026-03 的 MEM）才剛開始加入。這讓 VLA 完全不需要 LLM serving 中最複雜的 KV cache 管理。

## 5. 時間約束：硬即時、閉環、多頻率

| | LLM serving | 機器人推論 |
|---|---|---|
| 延遲要求 | 軟性（TTFT < 1 s、TPOT < 50 ms 是體驗問題） | **硬性**：chunk 在用完前必須產出，否則機器人停頓或失控 |
| 迴路 | 開放迴路（人讀完再回） | **閉迴路**：動作改變世界 → 下一次觀測 |
| 頻率 | 單一 | **多頻率**：相機 30 Hz、推論 2–10 Hz、控制 50–200 Hz |
| 延遲的代價 | 使用者等待 | **任務成功率下降**（動作與觀測錯位） |
| 尾延遲 | p99 重要 | **最壞情況**重要（安全） |

延遲直接影響任務成功率，這是為什麼 Physical Intelligence 發展 real-time chunking、為什麼 DreamZero 要把預測幀換成真實觀測。

## 6. 批次：b = 1 vs 大 batch

LLM serving 的經濟學建立在 batch 上：b=64 時權重讀取被 64 個使用者分攤（見 [03](03-memory-io.md)，權重佔流量從 93% 降到 18%）。

機器人推論**通常 b = 1**：一台機器人、一個請求、等不了。這讓 VLA 永遠停在「權重頻寬瓶頸」那一側。例外：
- **JEPA-MPC**：候選軌跡天然平行（b = 400）。
- **多手臂 / 多機器人**共用一顆晶片：可以把多個請求的 expert 步驟對齊批次。
- **Best-of-N 動作取樣**：同時取樣多條 action chunk 選最佳，可把 M 從 50 推到數百。

## 7. 計算特性

| 指標 | LLM decode | LLM prefill | VLA flow 迴圈 | 影片 DiT |
|---|---|---|---|---|
| GEMM 的 M | 1–batch | 數千 | **40–51** | 數千～七萬 |
| 算術強度 | 1–14 | ~2,000 | **40–60** | 2,500–70,000 |
| 瓶頸 | 頻寬 | 算力 | **頻寬** | 算力 |
| 注意力佔比 | 隨 context 增（8K: 24%、128K: 83%） | 低 | 低（4–15%） | 高（24–83%） |
| 重複單位 | 全模型 | – | **小型 expert**（0.1–0.5 B） | 全模型 |

VLA 是一種**新的中間形態**：「一次中等規模 prefill + 對小模型做少量固定次數的低 M 迴圈」。它不是 LLM decode（M=1，重讀全模型），也不是 prefill。

## 8. 數值與架構細節

| | LLM | 機器人 / 世界模型 |
|---|---|---|
| 時間條件 | 無 | flow/diffusion 時間步 → **adaLN / adaRMSNorm** 每層調變 |
| 位置編碼 | 1D RoPE | **3D RoPE**（時間 × 高 × 寬），動作 token 另有位置 |
| 注意力遮罩 | causal | prefix 雙向 + suffix 因果（π0）；frame-causal（V-JEPA）；block-causal + 滑動視窗（Matrix-Game） |
| 跨注意力 | 少見 | 普遍（GR00T、SmolVLA、Wan/Cosmos 的文字/影像條件） |
| 多模型組合 | 單一模型 | **異質子模型**：ViT + VLM + expert（不同寬度，π0 1024 vs 2048）、T5/CLIP + DiT + VAE |
| 非 Transformer 部分 | 幾乎無 | **3D 卷積 VAE**（世界模型）、Euler 更新、CFG 混合 |
| 層截斷 | 不會 | GR00T 只用 12/28 層、SmolVLA 16/32 層——**backbone 被當成特徵抽取器** |
| 精度敏感度 | 權重 INT4 已普遍 | 動作頭輸出直接驅動馬達：量化誤差 → 軌跡誤差；ODE 多步積分會累積誤差 |

## 9. 系統層

| | LLM | 機器人 / 世界模型 |
|---|---|---|
| 部署位置 | 資料中心 | **機器人上**（邊緣 SoC，30–130 W） |
| 擴展方式 | 多卡、tensor/pipeline parallel | 單晶片為主；WAM 才需要資料中心等級 |
| I/O | 網路請求 | 相機 → ISP → 加速器、加速器 → 馬達控制器 |
| 可靠性 | 重試即可 | 安全關鍵，需要確定性延遲 |
| 能效指標 | tokens / J | **控制週期 / J**（電池續航直接受影響） |

## 10. 評估與最佳化目標

LLM 的推論最佳化追求「同樣品質下最大吞吐」；機器人推論追求「**在固定延遲預算內，最大化任務成功率**」。這導致非常不同的取捨：
- 寧可多花 FLOPs 換更準的動作（如 10 步而非 1 步），只要延遲預算內。
- 寧可犧牲吞吐換確定性（不做動態 batching）。
- 世界模型的 CFG 讓每步計算翻倍，是為了生成品質（一致性、物理合理性），而非 LLM 中常見的「省一點是一點」。

---

## 一句話總結

> **LLM 是「一個巨大模型、一次一個 token、狀態不斷長大、追求吞吐」；VLA 是「一次看懂場景、再對一個小模型反覆精煉一整段動作、狀態固定且很小、追求確定延遲」；影片世界模型則是「一個大模型反覆精煉整段時空 token、注意力與 activation 主導、算力瓶頸」。**

三者在同一顆晶片上會落在 roofline 的三個不同位置：LLM decode 在最左邊（AI ≈ 1）、VLA 迴圈在中間偏左（AI ≈ 50）、影片 DiT 在最右邊（AI > 2,500）。
