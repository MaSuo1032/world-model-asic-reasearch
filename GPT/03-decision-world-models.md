# 機器生成足以做決策的未來

## 狀態應保留什麼

以機械手臂抓杯子為例，杯緣、把手、接觸、速度與滑動影響選擇；花紋可能較不重要。重量、摩擦與遮擋物需要估計或保留不確定性，不能只靠單張影像猜成確定值。

Latent 的目標是保留能預測動作後果的資訊，而不只是縮小影像。是否足夠由任務決定：對平移足夠的狀態，未必足以預測液體濺出。

## 參考系統

    感測與歷史 -> Encoder / 狀態估計 -> 目前信念 b[t]
                                              |
    Policy / 高層子目標 -> 候選動作 --------> 世界模型 rollout
                                              |
                                  Reward / Value / 約束 / 風險
                                              |
                                    選近期動作 -> 執行
                                              |
                                    新觀測回到狀態估計

概念公式：

    b[t] = E(b[t-1], o[t], a[t-1])
    b_hat[t+1] ~ F(b[t], a[t])

    J = E[sum(k=0..H-1) gamma^k * r(b_hat[t+k], a[t+k])
          + gamma^H * V(b_hat[t+H])]

b 可以是向量、tokens、物件表示或結構化信念，不要求顯式機率密度。模型可能還包含約束檢查與風險項。

每次執行第一步或短 action chunk，再觀測重規劃。選擇 chunk 長度時需考慮感測延遲、環境變化與模型誤差。

## 為何需要 terminal value 或子目標

短 rollout 只看到局部未來。若評分只用「離最終目標多近」，會偏好短期貪婪動作，無法處理先繞路或先移開障礙的任務。

Terminal value 估計 rollout 結束後的價值；階層式子目標讓短期規劃有可達成的目標。它們都需要學習與驗證，不能假設一定準確。TD-MPC 的潛在動態＋terminal value 是一個基線。[官方程式庫](https://github.com/nicklashansen/tdmpc)

2026 的短程規劃限制研究是在特定目標評分及任務設定下得到結果，不能當成使用不同 value 或子目標方法時也必然成立的定理。[研究](https://arxiv.org/abs/2609.39235)

## 三種部署

| 方式 | 世界模型運作位置 | 部署負載 |
|---|---|---|
| Online MPC | 每次決策 | Encoder、候選 rollout、評分、搜尋 |
| Imagination-trained policy | 大量運算在訓練端 | Policy 前向；未必執行世界模型 |
| Policy proposals + world-model scoring | 線上少數候選評估 | Policy 加有界的模型搜尋 |

Dreamer 4 說明想像可用於訓練行為。[論文](https://arxiv.org/abs/2509.24527)

本報告建議先研究第三種，因為計算預算容易控制，也容易與原本 policy 對照。這是工程建議，不是實驗結論。

## 平行性與正確性

候選維度 K 可平行；時間 horizon H 一般依賴前一步。若採取一次輸出整段軌跡的架構，執行形狀會不同，不適用所有逐步 rollout 的假設。

可以用多個隨機結果或模型評估不確定性，但多樣性不自動代表校準良好。需要測試模型能否辨識不可靠區域。

增加候選數可能讓搜尋找到利用模型漏洞的方案。必須以真實或可信環境中的閉環成功驗證，不能只看模型內的高分。

## 訓練與量化應對齊決策

除了狀態預測損失，也要檢查：

- 是否把好的候選排在前面。
- 對接觸、遮擋、滑動與時間的預測是否足夠。
- 預測失準時是否過度自信。
- 量化誤差是否改變最終選擇。
- 執行後重觀測能否恢復，而非持續漂移。

低 latent MSE 不保證高任務成功。量化應分別測單步、多步及閉環，不能僅以視覺品質或單層誤差決定精度。
